# 首次取钥排障与复盘

首次配置需要使用同一个已授权账号，以及同一安装环境中的 setup 入口。已有日常配置时，用独立的配置和数据目录做验收，保留日常配置及本地库。本人完成微信登录，不要在聊天中提供或输出凭据。

## 操作顺序

1. 准备账号目录、已确认的会话稳定标识和时区。使用[安装指南](INSTALLATION.md)中的命令。隔离验收时显式指定独立的 `--config` 和 `--data-home`，并保存这两个路径以供重试。它们是 Walden 的配置和数据目录，账号目录仍通过 `--account-root` 指定。
2. 等待 setup 的结果。等待本人登录或扫码与副本启动失败是不同阶段，请先查看回执。本人在微信上完成登录。
3. 重试前确认上一轮捕获结束，目标和调试器组清理均为 confirmed。保持同一配置和数据目录，让已安装的 setup 校验并复用该配置对应的受保护副本。身份或来源冲突、清理状态不明时停止，先排查，不能强行复用。
4. 如果系统阻止副本执行，先确认提示对应本轮受保护的调试副本。只有本人识别并信任该副本后，才由本人按系统支持的提示决定是否允许。没有提示或无法确认对象时暂停执行和重试，继续只读核实对象。
5. 如果需要退出日常微信，先取得用户同意并正常退出，确认启动锁释放后再重试。完成后按授权重新打开日常微信，由本人确认登录。
6. 完成时核对回执中 `credential_capture=captured_and_verified`，状态为 `configured` 或 `configured_with_voice_incomplete`，并确认验证、保存、配置及目标和调试器组清理完成。后者需单独说明语音缺口。配置完成后仍要在授权范围内初始化副本并检查覆盖，历史可能需要多轮同步。

## 一次实际排查

0.7.9 的一次首次配置在调试副本签名前因 FinderInfo 属性失败。0.8 已加入针对受保护副本的属性处理和严格验签。

随后的一次 0.8 验收中，副本签名和验签通过，但系统日志记录 Gatekeeper 终止了该副本。用户允许明确识别的同一副本后重试，目标退出 255，当时日常微信持有启动锁。用户同意正常退出日常微信并确认锁释放后，使用同一安装和同一副本再次执行 setup，约 44 秒返回 `configured` / `captured_and_verified`，校验、保存与清理完成。日常微信重新打开后，用户确认登录。该时间只覆盖一次 setup 调用，不包括此前排查和用户操作。

此前成功的 0.4.3 与本次 0.8 的启动脚本、微信构建和副本签名指纹一致，系统版本不同。证据尚不能确定系统升级导致了该问题。退出码 255 并不单独证明启动锁冲突，退出码 9 也不能单独证明 Gatekeeper 拒绝。静态执行评估结果不能单独决定后续实际启动结果。本次成功没有修改 Developer Tools 设置，它不是首次安装的必做项。
